## 1. 개요

YTLoader는 yt-dlp 기반 개인용 YouTube 다운로더다. 데스크톱판(Windows, PowerShell
WinForms)이 이미 있고, 이 프로젝트는 같은 기능을 Android 앱으로 다시 만든다.
데스크톱판 원본은 [reference/YTLoader.ps1](reference/YTLoader.ps1)에 있으며,
이 명세와 원본이 다르게 읽히면 **이 명세가 우선**이고, 명세가 다루지 않는 세부 동작은
**원본을 따른다**.

- 배포: Google Play가 아닌 GitHub Releases의 APK (Play 정책상 게시 불가 — 10장 참고).
- 사용자: 개발자 본인과 지인. 한국어 UI.

## 2. 목표 / 비목표

### 목표

- 데스크톱판의 다운로드 기능(모드, 포맷, 품질, 썸네일, 메타데이터, 재생목록)을 동일한
  yt-dlp 옵션으로 제공한다.
- YouTube 앱의 **공유 → YTLoader**로 URL을 받는다 (모바일의 주 진입 경로).
- 화면이 꺼지거나 다른 앱으로 전환해도 다운로드가 계속되고, 알림으로 진행률을 본다.
- 앱 안에서 yt-dlp를 업데이트한다 (YouTube 변경으로 다운로드가 깨질 때의 해결책).
- YouTube 로그인(쿠키)으로 비공개 · 연령 제한 · 멤버십 영상을 받는다.

### 비목표 (v1에서 만들지 않음)

- 다운로드 큐 / 동시 다운로드 (데스크톱판도 한 번에 하나).
- 저장 폴더 직접 선택(SAF 트리). 저장 위치는 고정 (FR-6).
- YouTube 외 사이트 대응 보장 (yt-dlp가 되면 되지만 테스트 대상 아님).
- 다운로드 기록 화면, 내장 플레이어, 검색.
- 다국어 (한국어만).
- Google Play 배포, 자동 업데이트(앱 자체), 분석/광고 SDK.

## 3. 사용자 시나리오

- **S1 공유로 받기**: YouTube 앱에서 영상 → 공유 → YTLoader → 메인 화면에 URL이 채워짐
  → 지난번 옵션 그대로 [다운로드] → 알림에 진행률 → 완료 알림 탭 → 파일 열림.
- **S2 붙여넣기로 받기**: 앱 실행 → [붙여넣기] → 모드/포맷 선택 → [다운로드].
- **S3 다운로드 실패 → 업데이트**: 오류 메시지의 안내대로 [yt-dlp 업데이트] → 재시도 성공.
- **S4 비공개 영상**: [로그인] → 앱 내 브라우저에서 Google 로그인 → 자동으로 닫히고
  "로그인됨" 표시 → 비공개 영상 다운로드 성공.
- **S5 로그인이 막힌 경우**: PC에서 내보낸 cookies.txt를 [cookies.txt 가져오기]로 등록
  → S4와 같은 결과.

## 4. 기능 요구사항 (FR)

각 FR의 "수용 기준"이 그 기능의 완료 조건이다.

### FR-1 URL 입력

- 텍스트 필드 + [붙여넣기] 버튼(클립보드 텍스트를 필드에 넣음).
- 다운로드 시 앞뒤 공백 제거. 빈 값이면 "URL을 입력해 주세요." 표시 후 중단.
- 수용 기준: 클립보드의 `https://youtu.be/jNQXAC9IVRw`가 [붙여넣기]로 필드에 들어간다.

### FR-2 공유 인텐트 수신

- `ACTION_SEND`, `text/plain`을 받는다. `EXTRA_TEXT`에서 **첫 번째 http(s) URL**을
  추출해 URL 필드에 넣는다. 자동으로 다운로드를 시작하지 않는다(옵션 확인 기회를 줌).
- 공유 텍스트에 URL이 없으면 "공유된 내용에서 URL을 찾지 못했습니다." 표시.
- 앱이 이미 열려 있으면 같은 화면에서 URL만 교체한다(새 화면을 쌓지 않음 — YouTube 앱의
  작업 스택 안에 두 번째 인스턴스가 생기지 않아야 한다).
- 다운로드 진행 중에 공유받으면 URL만 채우고 "진행 중인 다운로드가 끝난 뒤 시작하세요." 표시.
- 수용 기준: PowerShell에서
  `adb shell "am start -a android.intent.action.SEND -t text/plain --es android.intent.extra.TEXT 'title https://youtu.be/jNQXAC9IVRw' -n io.github.dev1ck.ytloader/.MainActivity"`
  실행 시 URL 필드가 `https://youtu.be/jNQXAC9IVRw`가 된다. (공백이 든 값은 원격 셸에서
  쪼개지므로 작은따옴표로 한 번 더 감싼다.) 실기기에서 YouTube 앱 → 공유로도 한 번 확인한다.

### FR-3 모드 / 포맷 / 품질

- 모드: **오디오만**(기본) / **영상+오디오**.
- 모드에 따라 포맷·품질 목록이 바뀐다 (6장 카탈로그). 모드를 전환하면 그 모드에서
  마지막으로 고른 포맷·품질을 복원하고, 기록이 없으면 첫 항목을 선택한다 (FR-11).
- 품질 라벨: 오디오 모드 "음질", 영상 모드 "해상도".
- 오디오 모드에서 무손실·원본 포맷(flac, wav, original)은 품질 선택 비활성.
- 수용 기준: 6장의 표와 항목·순서·라벨이 정확히 같다.

### FR-4 추가 옵션

| 옵션 | 기본값 | 활성 조건 |
|---|---|---|
| 썸네일 삽입 | 켜짐 | 선택 포맷이 썸네일 지원 포맷일 때만 (6장) |
| 메타데이터 삽입 | 켜짐 | 항상 |
| 재생목록 전체 | 꺼짐 | 항상 |

- 비활성 옵션은 체크 상태와 무관하게 yt-dlp에 전달하지 않는다.
- 재생목록 전체: URL에 재생목록이 있으면 전체를 `<재생목록 이름>` 하위 폴더에 받는다.
  끄면 해당 영상 하나만 받는다.

### FR-5 다운로드 실행 · 진행 표시 · 취소

- [다운로드]를 누르면 포그라운드 서비스에서 실행한다. 실행 중에는 입력 컨트롤 전체와
  [업데이트], 로그인 영역이 비활성, [취소]만 활성.
- 진행 표시(화면 + 알림 동일 문구):

  | yt-dlp 출력 | 표시 문구 | 진행률 |
  |---|---|---|
  | `[download]  42.3% of 3.2MiB at 1.1MiB/s ETA 00:02` | `다운로드 중... 42.3% of 3.2MiB at 1.1MiB/s ETA 00:02` | 42.3% |
  | `[download] Downloading item 3 of 12` | `재생목록 3 / 12 항목 처리 중...` | 유지 |
  | `[ExtractAudio] ...` 등 후처리 태그 | `변환 / 후처리 중... [ExtractAudio]` | 100% |
  | (시작 직후) | `다운로드 준비 중...` | 0% |

  후처리 태그: `ExtractAudio, Merger, VideoRemuxer, VideoConvertor, EmbedThumbnail, Metadata, FixupM4a, FixupM3u8`.
- 취소: 화면의 [취소] 또는 알림의 [취소] 액션. 하위 ffmpeg 포함 프로세스 종료,
  작업 폴더 삭제(재생목록의 완성된 항목은 FR-7 규칙대로 먼저 저장),
  "다운로드가 취소되었습니다." 표시.
- 수용 기준: "Me at the zoo"(jNQXAC9IVRw) 다운로드 중 진행률 알림이 갱신되고,
  홈으로 나가도 완료된다. 재생목록 다운로드 중 [취소] 시 10초 안에 멈추고 부분 파일이
  공용 저장소에 남지 않는다.

### FR-6 저장

- 저장 위치: 공용 `Download/YTLoader/` (MediaStore.Downloads). 재생목록 전체면
  `Download/YTLoader/<재생목록 이름>/`.
- 파일명: 데스크톱판과 같은 템플릿 — 단일 `<제목>.<확장자>`,
  재생목록 `<번호 3자리> - <제목>.<확장자>`.
- 다운로드 중간 파일은 앱 전용 작업 폴더에 두고, **성공 후에만** 공용 저장소로 옮긴다.
- 저장소 권한 요청 없이 동작한다 (minSdk 29 + MediaStore).
- 수용 기준: 완료 후 파일 관리자 앱의 `Download/YTLoader/`에 파일이 보이고,
  음악 앱에서 재생된다.

### FR-7 완료 / 실패 안내

- 성공: "다운로드 완료" 알림 + 화면 상태 `다운로드 완료 (Download/YTLoader)`.
  알림 탭 시 저장된 첫 번째 파일을 연다(재생목록이면 첫 항목).
- 실패: 화면에 오류 대화상자 — 종료 코드(라이브러리가 알려주지 않으면 "알 수 없음"),
  yt-dlp의 마지막 `ERROR:` 줄, 안내 문구(7장). 실패 알림도 표시.
- 재생목록 전체 다운로드가 실패하거나 취소돼도, **이미 완성된 항목 파일은 저장**한다
  (데스크톱판도 남김). 문구 끝에 "(완료된 N개 파일은 저장됨)"을 덧붙인다.
  단일 영상의 실패·취소에서는 아무것도 저장하지 않는다.

### FR-8 yt-dlp 업데이트

- ⚙ 설정 시트의 "다운로드 엔진" 항목에 현재 yt-dlp 버전과 [업데이트] 버튼 (2026-10-31 UI 개편으로 메인 하단에서 이동).
- 업데이트는 STABLE 채널. 진행 중 다른 조작 비활성.
- 결과 대화상자: "최신 버전으로 업데이트했습니다 (vX)" / "이미 최신 버전입니다 (vX)" /
  "업데이트 실패: <사유>".
- 수용 기준: 버튼 실행 후 표시 버전이 라이브러리가 보고하는 버전과 같다.

### FR-9 YouTube 로그인 (앱 내 브라우저)

- [로그인] → 전체 화면 WebView로 Google 로그인 페이지(데스크톱판과 같은 URL)를 연다.
  상단 안내(고정 문구): "로그인되면 자동으로 닫힙니다. 로그인이 막히면 닫은 뒤
  [cookies.txt 가져오기]를 사용하세요." — Google의 차단은 앱이 감지할 수 없으므로 항상 표시.
- YouTube 계정 쿠키(`SAPISID` 또는 `__Secure-3PAPISID`)가 youtube.com에 생기면
  쿠키를 cookies.txt로 저장하고 화면을 자동으로 닫는다. 이때 [로그인 쿠키 사용]을
  켜짐으로 바꾸고 저장한다(데스크톱판과 동일). FR-10 가져오기 성공 시에도 같다.
- 사용자가 뒤로가기/닫기로 나가면 "로그인이 취소되었습니다."
- 로그인 영역은 ⚙ 설정 시트의 "YouTube 로그인" 항목 (2026-10-31 UI 개편으로 메인에서 이동).
  메인 상단 앱바에는 로그인 상태일 때만 `로그인됨` 칩을 보인다(누르면 설정 시트).
  - 로그아웃 상태: `로그인 안 됨`, [로그인], [cookies.txt 가져오기]
  - 로그인 상태: `로그인됨 (yyyy-MM-dd)`, [로그인 쿠키 사용] 스위치(기본 켜짐), [로그아웃]
- [로그인 쿠키 사용]이 켜져 있을 때만 다운로드에 쿠키를 전달한다. 스위치 설명:
  "공개 영상만 받을 때는 꺼도 됩니다. 계정 보호를 위해 보조 계정 사용을 권장합니다."
- [로그아웃]: 확인 대화상자 → cookies.txt 삭제 + WebView 쿠키·저장소 전부 삭제.
- 수용 기준: 실기기에서 실제 계정으로 로그인 후 비공개(또는 연령 제한) 영상이 받아진다.
  — **사용자가 직접 검증**한다(계정 필요).

### FR-10 cookies.txt 가져오기 (로그인 대체 경로)

- 시스템 파일 선택기로 파일 하나를 고른다.
- 검증: Netscape 형식이고 `youtube.com` 도메인 줄이 1개 이상. 아니면
  "YouTube 쿠키가 들어 있는 cookies.txt가 아닙니다." 표시, 기존 상태 유지.
- 통과하면 앱 전용 위치로 복사하고 로그인 상태가 된다 (FR-9와 같은 상태).
- 수용 기준: 데스크톱판이 만든 `%LOCALAPPDATA%\YTLoader\cookies.txt`를 가져오면
  로그인 상태가 된다.

### FR-11 설정 유지

- 마지막으로 쓴 모드, 포맷, 품질, 3개 옵션, [로그인 쿠키 사용]을 저장하고 다음 실행 때 복원.
- URL은 저장하지 않는다.

### FR-12 완료 후 열기 (2026-10-31 추가)

- 다운로드가 끝나면 하단 결과 줄에 [열기]. 누르면 저장된 첫 파일을 연다(알림 탭과 같음).
  열 수 있는 앱이 없으면 "이 파일을 열 수 있는 앱이 없습니다.".

### FR-13 클립보드 링크 제안 (2026-10-31 추가)

- 화면이 포커스를 얻을 때 URL 입력란이 비어 있고 클립보드에 YouTube 링크(youtube.com·youtu.be)가
  있으면 입력란 아래에 "클립보드 링크 붙여넣기 · <링크>" 칩을 보인다. 누르면 입력, ✕로 닫으면
  같은 링크는 다시 제안하지 않는다.
- 클립보드가 바뀌었을 때만 내용을 읽는다(Android 12+는 읽을 때마다 시스템 알림이 뜨므로).

### FR-14 제목 미리보기 (2026-10-31 추가)

- URL 입력란이 URL 하나로 채워지고 0.7초 동안 바뀌지 않으면 yt-dlp로 제목을 조회해 입력란 아래
  카드에 보인다. 조회 중 "제목 가져오는 중…", 실패 시 "제목을 가져오지 못했습니다. 그래도
  다운로드할 수 있습니다.". [재생목록 전체]가 켜져 있고 재생목록 링크면 재생목록 이름을 보인다.
- 엔진이 준비되지 않았거나 다운로드 중이면 조회하지 않고, 다운로드를 시작하면 진행 중인 조회를 취소한다
  (yt-dlp를 동시에 두 개 돌리지 않음). 로그인 쿠키 사용 조건은 다운로드와 같다.
- 조회는 약 5–10초 걸리고 데이터를 조금 쓴다.

## 5. 화면 명세

### 메인 화면 (2026-10-31 개편: 칩 + 하단 고정 버튼)


## 7. 오류 · 엣지 케이스

| 상황 | 기대 동작 |
|---|---|
| URL 비어 있음 | "URL을 입력해 주세요." 다운로드 시작 안 함 |
| 공유 텍스트에 URL 없음 | "공유된 내용에서 URL을 찾지 못했습니다." |
| yt-dlp 실패 (일반) | 오류 대화상자 + 안내: "yt-dlp 업데이트 후 다시 시도해 보세요." |
| 마지막 오류에 `sign in`, `login`, `private`, `members`, `confirm your age` 중 하나 포함 (대소문자 무시) | 안내에 추가: "비공개 · 연령 제한 · 멤버십 영상이라면 로그인이 필요합니다. 이미 로그인했다면 다시 로그인해 보세요." |
| 네트워크 끊김 | yt-dlp 오류로 처리 (위와 같음) |
| 엔진 초기화 실패 | "yt-dlp 엔진을 준비하지 못했습니다: <사유>" 대화상자, 다운로드 비활성 |
| 알림 권한 거부 (API 33+) | 다운로드는 정상 동작, 진행은 앱 화면에서만 보임. 권한은 첫 다운로드 때 한 번 요청 |
| Android 15+ dataSync 6시간 제한 도달 | 작업 취소 처리 + "시스템 제한으로 다운로드가 중단되었습니다." 알림 |
| 앱 프로세스 강제 종료 | 다음 실행 시 남은 작업 폴더 삭제. 상태는 대기 |
| 공용 저장소에 같은 이름 존재 | MediaStore의 자동 이름 변경(` (1)`)을 그대로 받아들임 |
| 저장 공간 부족 | yt-dlp 또는 복사 오류로 실패 처리, 작업 폴더 삭제 |
| 파일명에 특수문자 | Windows 호환 파일명으로 변환 (데스크톱판과 같은 결과) |
| 업데이트 중 네트워크 오류 | "업데이트 실패: <사유>", 기존 버전 유지 |
| 로그인 화면에서 Google이 로그인을 막음 | 사용자는 닫고 FR-10으로 진행 (배너의 고정 문구가 안내) |

## 8. 비기능 요구사항 (NFR)

- **NFR-1 플랫폼**: minSdk 29 (Android 10), targetSdk 36, compileSdk 37. 주 대상 ABI arm64-v8a.
- **NFR-2 개인정보**: 쿠키 값과 cookies.txt 내용을 로그 · 알림 · 오류 메시지에 출력하지
  않는다. 쿠키 파일은 앱 전용 비백업 영역에 저장하고 백업에서 제외한다.
- **NFR-3 네트워크**: YouTube/Google(다운로드·로그인)과 GitHub(yt-dlp 업데이트) 외의
  통신이 없다. 분석·광고·크래시 리포팅 SDK 없음.
- **NFR-4 응답성**: 메인 스레드에서 yt-dlp 실행, 파일 복사, 엔진 초기화를 하지 않는다.
- **NFR-5 크기**: 릴리스 APK는 arm64-v8a 단일 ABI로 만든다 (Python·ffmpeg 포함으로
  수십 MB는 정상).
- **NFR-6 언어**: UI 문자열은 `strings.xml`(한국어)로 관리한다.

## 9. 데스크톱판과의 차이

| 항목 | 데스크톱판 | Android판 | 이유 |
|---|---|---|---|
| 실행 엔진 | yt-dlp.exe / ffmpeg.exe / deno.exe | youtubedl-android 라이브러리(Python·yt-dlp·ffmpeg·QuickJS 내장) | Android에서 exe 실행 불가 |
| URL 입력 | 텍스트 박스 | + 공유 인텐트 | 모바일 주 사용 경로 |
| 저장 위치 | 사용자 선택 (기본 Downloads) | `Download/YTLoader/` 고정 | 저장소 권한 없이 동작 |
| 진행 | 창 안 진행률 | + 알림, 백그라운드 계속 | 모바일 생명주기 |
| 로그인 | 전용 Chrome 프로필 + DevTools로 쿠키 추출 | 앱 내 WebView + cookies.txt 가져오기 | Android에 해당 방식 없음 |
| JS 런타임 | deno | QuickJS (라이브러리 내장) | 크기 (deno 약 95MB) |
| 설정 유지 | 없음 | 있음 (FR-11) | 모바일에서 반복 입력 부담 |

## 10. 열린 문제

결정권자를 표기한다. "사용자" 항목은 구현 세션이 임의로 정하지 않고 보고 후 확인받는다.

| ID | 문제 | 해소 시점 | 결정권자 |
|---|---|---|---|
| O-1 | 앱 내 WebView에서 Google 로그인이 막히는가 (Google은 임베디드 브라우저 로그인을 차단할 수 있음) | M5 실기기 검증 | 사용자 검증 → 막히면 User-Agent 조정 시도, 그래도 막히면 FR-10만 제공 |
| O-2 | 내장 QuickJS로 YouTube 추출 시간이 실용적인가 (구버전 QuickJS는 수 분 걸릴 수 있음) | M1 스파이크 | 측정값 보고 후 사용자 — 에뮬레이터 측정(2026-10-31): 최신 yt-dlp에서 추출 약 10초, 19초 영상 mp3 약 24초로 실용적. 실기기(SM-S948N, 2026-10-31): mp3 12–14초, mp4 1080 16초로 실용적 — **해소** |
| O-3 | 라이브러리 내장 Python에서 포맷별 썸네일 삽입이 되는가 (m4a/opus/flac은 mutagen 필요 가능) — **해소(2026-10-31)**: 내장 Python에 mutagen 있음. mp3·m4a·opus·flac·mp4는 attached_pic 스트림, mkv는 첨부 파일로 삽입 확인. 표 변경 없음 | M3 | 구현자: 안 되는 포맷은 이 문서 6장 표의 "썸네일 지원"을 X로 고치고, 카탈로그·테스트·골든 예제를 함께 갱신한 뒤 보고 |
| O-4 | 앱 라이선스 (Seal은 GPL-3.0, youtubedl-android도 **GPL-3.0** 확인 — 포함해 배포하면 앱도 GPL-3.0 호환이어야 함) — **결정(2026-10-31): GPL-3.0**, 저장소 루트 `LICENSE` | 릴리스 전 | 사용자 |
| O-5 | 패키지명 | — | 결정됨: `io.github.dev1ck.ytloader`로 진행하고 멈추지 않는다. 사용자가 바꾸라고 할 때만 변경 |

다운로드 금지(yt-dlp 앱 내 업데이트가 해당), 저작물 무단 다운로드 앱 금지.
